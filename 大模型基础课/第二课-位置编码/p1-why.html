为什么自注意力需要位置编码？

因为自注意力本质是对一个"集合"做加权平均——它天生看不见顺序。不额外告诉它"谁在第几位"，"猫追狗"和"狗追猫"在它眼里就是同一堆词。

关键概念： 置换等变 permutation equivariance 因果掩码 causal mask 绝对 vs 相对

① 自注意力做了什么

给定一串 token 的向量 x₁ … xₙ，自注意力先把每个向量投影成 Query / Key / Value，然后每个位置的输出是所有位置 Value 的加权和，权重由 Q·K 的相似度决定：

Attention(Q, K, V) = softmax( QK⊤ / √d ) · V 注意：这个式子里没有任何和"位置 i、j"绑定的项。权重只取决于向量内容 qᵢ·kⱼ，与它们排在第几位无关。

② 关键性质：置换等变

如果把输入序列的顺序打乱（做一个置换 π），自注意力的输出只会跟着同样打乱，每个 token 算出来的表示数值完全不变。用一句话说：

🔑 Attention(πX) = π·Attention(X)
打乱输入 → 输出原样打乱，但"每个 token 得到的向量"一模一样。这叫置换等变。它意味着：纯自注意力无法区分词序。前馈层 FFN 是逐位置独立的，也帮不上忙。

这正是问题所在。语言的含义高度依赖顺序：

  • "猫 追 狗" vs "狗 追 猫"——同一堆词，意思相反。
  • "不 好" vs "好 不"——顺序决定语气。

如果模型看到的只是"一袋子词"（bag of words），它永远学不会这种区别。所以必须把位置信息显式地喂进去——这就是位置编码（Positional Encoding）存在的全部理由。

③ 亲手打乱看看（可交互）

下面是一句话的 token。点"打乱顺序"：在没有位置编码的假想里，注意力只把这些词看成一个集合，含义无从区分。给每个 token 贴上位置标签后，模型才能分清词序。

④ 一个例外：因果掩码其实"偷偷"泄漏了位置

上面说的是标准（双向）自注意力。但今天的大模型多是 decoder-only + 因果掩码：第 i 个 token 只能看到 1…i，看不到未来。

👀 掩码 = 一种隐含的位置信号
第 1 个 token 只能看到 1 个词，第 5 个能看到 5 个词……"我能看到几个前文"本身就编码了"我在第几位"。2023 年的研究（NoPE）正是利用这一点，论证 decoder-only 模型即使不加任何显式位置编码也能学到顺序。这是本课后半程的一个重要伏笔。

⑤ 两大家族：绝对 vs 相对

解决方案历史上分成两条大路，后面每一页都能归到这两类（或它们的融合）：

家族思路代表方法
绝对位置给"第 i 个位置"一个专属编码，加到词向量上Sinusoidal · Learned
相对位置只编码"两个 token 相距多远"，注入到注意力打分里Relative · T5 bias
融合 / 现代主流用绝对形式实现相对效果，或直接改注意力偏置RoPE · ALiBi
