2022–2024 · 大词表时代

tiktoken 与"大词表"时代

算法还是字节级 BPE，但工程上进入了「大词表」竞赛——从 GPT-2 的 5 万，一路涨到 GPT-4o 的约 20 万、Gemma 的 25.6 万；同时预切分正则也在进化（如数字按 1–3 位分组）。

被这些模型使用：GPT-3.5/4 cl100kGPT-4o o200kQwen 152kDeepSeek 128kLlama3 128kGemma 256k

① 出身：tiktoken 是 OpenAI 的 BPE 实现库

先厘清一点：tiktoken 不是新算法。它是 OpenAI 开源的一个高性能 字节级 BPE（BBPE）实现库，Rust 内核 + Python 绑定，仓库在 github.com/openai/tiktoken。算法内核就是上一节的字节级 BPE（256 字节起步、正则预切分、无 unk）——tiktoken 提供的是「怎么把它跑得又快又标准」，以及一套命名好的 encoding（词表 + 预切分正则的组合）。这一节真正的主角，是这套 encoding 背后的一个清晰历史趋势：词表一路变大。

OpenAI 全系模型都用 tiktoken，不同世代对应不同的 encoding。三个里程碑（数据以 tiktoken 源码 openai_public.py 为准[1]）：

⚠️ 为什么词表数总是「对不上」？
你会在网上看到 cl100k 被写成 100,256、100,277、"100k"，o200k 被写成 199,998、200,000、200,019……这些差异几乎都来自「是否把特殊 token（如 <|endoftext|>、FIM 三件套、<|endofprompt|>）算进去」。以 tiktoken 源码为准：cl100k_base 基础 mergeable ranks 是 100,256、含特殊约 100,277；o200k_base 基础 199,998、含特殊约 200,019。课件里写「约 10 万 / 约 20 万」最稳妥，不要纠结个位数。同理 Qwen 的 151,643 / 151,936 / 152,064 三个数分别是「BPE 常规 token 数 / embedding 补齐后 / config 里的 vocab_size」，也是口径不同。

③ 为什么要更大的词表？

一句话：词表越大 → 压缩率越好 → 同样一段文本 token 数更少。高频的子词、整词、甚至短语能被并成单个 token。这带来三重直接收益：

  • 省算力：序列更短，而注意力是 O(n²)，token 数下降对训练 / 推理成本是超线性的节省。
  • 上下文更经用：同样的 context window（比如 128k token）能装下更多真实内容。
  • API 更便宜：按 token 计费时，压缩率好直接等于账单便宜。

而且多语言 / 中文·CJK / 代码受益最大。早期 50k 词表主要按英文语料学出，一个汉字常被切成 2–3 个字节 token，非英文成本极高；扩大词表并纳入多语言语料后，中文可做到约 1 token ≈ 1.5–1.8 个汉字（Qwen），代码里常见的缩进、关键字、符号组合也能整体成一个 token。这正是 Llama 3、DeepSeek-V3、Qwen、Kimi 把词表推到 128k–160k 的主因。

④ 为什么不无限大？（代价与权衡）

  • embedding / 输出层参数线性膨胀：embedding 参数量 = 词表大小 × hidden_dim，输出层（LM head）还要再来一份。词表从 32k 涨到 256k 是 8×，对中小模型这块占比可能高得离谱（如 Gemma-2B 的 embedding 就吃掉了模型相当比例的参数），显存和参数预算被挤占。
  • 稀有 token 训练不足（glitch token）：词表越大，长尾 token 出现频率越低，训练中见得少、embedding 学不透。这些「未充分训练 token」会触发异常行为——最著名的是 SolidGoldMagikarp 现象（某些几乎没被训练过的 token 会让模型胡言乱语 / 拒答）；DeepSeek-V3/r1 也被报告存在类似异常 token。
  • 收益递减：压缩率随词表增长是次线性的——32k → 128k 提升明显，再往上边际收益变小，而参数成本、稀有 token 风险却持续上升。
🔑 当前的甜蜜区间
在「压缩率」与「embedding 成本 + 稀有 token 可训练性」之间取折中，当前主流落在 128k–256k。词表大小本质是一个「压缩率 ↔ 参数量 / 可训练性」的权衡旋钮；过去几年因为多语言、代码需求和算力允许，整体右移到了 10 万–25 万量级，但不会无限右移。

⑤ 被哪些模型使用

tiktoken 的 encoding 直接对应 OpenAI 各代模型：

  • cl100k_base → GPT-3.5 / GPT-4
  • o200k_base → GPT-4o / o 系列（o1、o3 等）

而更重要的是，「tiktoken 风格的字节级大词表」已经成为开源 / 国产模型的主流范式，纷纷放弃早期的 SentencePiece 路线：

📎 小结 & 承上启下
tiktoken 本身没有改变算法——它仍是字节级 BPE；它标记的是一个工程趋势：词表从 5 万一路扩到 128k–256k，换来更好的压缩率（省算力、上下文更经用、API 更便宜），多语言与代码收益最大。但词表不能无限大：embedding / 输出层线性膨胀、稀有 token 训练不足（glitch token）、收益递减，把甜蜜区间钉在了 128k–256k。
那么下一个问题自然浮现：词表还能更大吗？还是干脆不要分词器？字节 / 字符级端到端模型（ByT5、字节潜变量等）能否绕开这整套权衡？这正是前沿趋势一节要探讨的。
