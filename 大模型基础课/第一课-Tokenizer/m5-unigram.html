Unigram 语言模型分词

和 BPE/WordPiece 反着来——先建一个大词表，再用 EM 一点点剪掉"删了最不心疼"的 token，直到目标大小；每个 token 带概率，一个词有多种切分可采样。

被这些模型使用：T5ALBERTXLNetmBART多语言模型

出身与论文

Unigram 语言模型分词由 Taku Kudo（工藤拓，SentencePiece 的作者）在 2018 年提出。它诞生的语境不只是"再造一个分词器"，而是要解决一个更实际的问题：同一个词其实有很多种合理切分，为什么训练时只能固定用一种？Unigram 给每个 token 配上概率，从而让"一个词有多种切分、可以采样"成为可能——这就是论文标题里的子词正则（subword regularization）。

2018 年（ACL）
作者

核心思想
自顶向下：先建一个远大于目标的种子词表，给每个子词一个概率，再用 EM 反复剪掉"删除后对语料似然损害最小"的一批 token，把词表缩到目标大小。因为每个 token 有概率，一个词天然有多种切分，可取最优也可采样。
一句话定位
BPE/WordPiece 是"从字符往上合并"，Unigram 是"从大词表往下剪枝"。方向完全相反，而且 Unigram 是唯一自带"每个 token 一个概率"和"一词多切分可采样"的方法。

核心算法

概率模型

把一句话 X 切成子词序列 x = (x₁, …, x_M)。在一元语言模型下，这段切分的概率是各子词概率之积；所有 token 的概率之和为 1：

P(x) = ∏_{i=1..M} p(xᵢ) ,     Σ_{x∈V} p(x) = 1

而一句话本身的概率，是它所有合法切分 S(X) 的概率之和：

P(X) = Σ_{x ∈ S(X)} P(x)

最可能的切分就是让 P(x) 最大的那个：

x* = argmax_{x ∈ S(X)} P(x)

这个 x* 可以用 Viterbi 算法 在"所有可能切分构成的格（lattice）"上高效求出。

训练算法（种子 → EM 剪枝）

1. 建一个很大的种子词表（远大于目标），例如：所有单字符
   + 长度受限的所有子串 / 最频繁的一批 n-gram（常用后缀自动机
   Suffix Automaton 枚举）。务必包含所有单字符，保证任何串都可切分。
2. 初始化每个子词的概率 p(x)（如按子串频次）。
3. 重复，直到 |V| <= 目标大小：
   a. (EM 重估 p(x)) 固定词表，跑 EM：
        E 步：对每句话，在其"切分格"上做前向-后向 / Viterbi 式
              计算，得到每个子词的期望出现次数；
        M 步：令 p(x) 正比于其期望次数。迭代到收敛。
   b. 对每个子词 x，计算 loss_x = 若把 x 从词表移除，
        整个语料对数似然会下降多少（受影响的词用剩余片段重切）。
   c. 按 loss 排序。所有单字符永远保留（绝不剪，以保证全覆盖）；
        剪掉 loss 最小的一批（如底部 10~20% 的"最没用"token）。
   d. 若 |V| 仍高于目标，回到 (a)。
4. 输出最终词表及其概率 p(x)。

这里有两个关键点要抓住：（1）选择准则是"删掉谁语料似然损失最小"，这是一个更接近全局的判据（衡量的是这个 token 对整个语料的边际贡献），不像 BPE/WordPiece 那样一步步贪心地挑相邻对；（2）单字符永远不剪——因为只要保留全部单字符，任何字符串都一定还有合法切分，这就从结构上保证了零 OOV。

一处需要坦白的不确定性
论文对"种子词表怎么建"留有余地（频繁子串 / 后缀自动机枚举都行），具体选择由 SentencePiece 的实现敲定。但上面的 EM-剪枝循环 和 Viterbi 解码 是准确、可复现的。[1]

怎么切分（推理）

默认：Viterbi 解码 —— 返回 argmax_x P(x)，即唯一最可能的切分，
      用 p(x) 作为切分格上各片段的发射分数。

子词正则（训练期数据增强）：不取 1-best，而是从 l-best 候选里
      采样一个切分（或用前向过滤 / 后向采样），由温度参数 α 控制：
         P_sample(x) ∝ P(x)^α 。
      不同训练轮次里同一个词被切成不同样子 → 对模型起正则作用。

这就是 Unigram 最独特的能力：训练时按 P(x)^α 采样不同切分，等于对训练数据做增强，让模型见过同一个词的多种切法、更鲁棒（尤其在低资源、跨领域场景）。BPE 本身做不到这点，要靠额外的 BPE-dropout（Provilkov 等 2020，arXiv:1910.13267，靠随机跳过合并制造随机性）来近似。[2] 推理/部署时则通常回到默认的 Viterbi 1-best，取最稳的那一种切分。

一个具体例子

假设词表里有这些片段及概率（数值仅为示意）：

tokenp(x)tokenp(x)
hug0.30hu0.10
##s0.20g0.05
gs0.02s0.08

给 hugs 分词，几种合法切分和它们的概率（片段概率相乘）：

切分P(x) = 各片段概率之积结果
hug · s0.30 × 0.08 = 0.0240最高 → Viterbi 选它
hu · gs0.10 × 0.02 = 0.0020较低
hu · g · s0.10 × 0.05 × 0.08 = 0.0004更低

默认（Viterbi）：返回概率最高的 hug · s。子词正则（采样）：以正比于 P(x)^α 的概率，可能这一轮返回 hug · s、下一轮返回 hu · g · s——同一个词在不同 epoch 被切成不同样子，模型因此被"正则化"。这正是"一个词有多种切分、可采样"的直观含义，也是 BPE/WordPiece 那种"一词一切"做不到的。

与 BPE 的关键区别

最本质的一句话
BPE 自底向上、按频次、一词一切、无概率；Unigram 自顶向下、按似然、一词多切可采样、有概率。方向、判据、产物三处全反。
维度BPE / WordPieceUnigram LM
方向自底向上：从字符出发，逐步向上合并自顶向下：从大词表出发，逐步剪枝
选择准则贪心：最频繁的对（BPE）/ 似然比最优的对（WordPiece）全局：移除"最不减少语料似然"的 token（EM）
每个 token 的信息无（只有一个合并顺序）一个显式概率 p(x)
每个词的切分数恰好一种（确定）多种，带分数；可取最优或采样
能否原生正则不能（需 BPE-dropout）能，原生支持（子词正则）

各自的取舍：Unigram 优化的是一个更干净的概率目标，通过采样白送一份正则化，切分往往更鲁棒（尤其低资源、跨领域）。代价是训练更重——EM + 反复的"格上重切分"和剪枝，比 BPE 那个简单的合并循环慢，模型概念上也更复杂。

被哪些模型使用

Unigram 是很多现代分词器背后的默认算法，尤其在多语言场景：

T5 ALBERT XLNet mBART 多语言模型

T5、ALBERT、XLNet、mBART 以及很多多语言模型都用它。更重要的是：Unigram 是 SentencePiece 的默认 model_type（--model_type=unigram）——你在很多项目里用 SentencePiece 却没特意指定算法，用到的就是 Unigram。

小结 · 承上启下
Unigram 把分词从"合并"翻转成"剪枝"：先撒一张大词表，用 EM 反复重估概率、按"删了最不心疼"的标准剪到目标大小；每个 token 带概率，一个词因此可以有多种切分——取最优用 Viterbi，采样则得到子词正则。它和 BPE 的对立可以浓缩成一句：自顶向下 / 似然 / 一词多切 / 有概率。而承载它、也承载 BPE 的那个工程框架，正是下一节要讲的 SentencePiece——它用 ▁ 把空格也当成普通字符，让整套子词分词变得语言无关、无损可逆。
