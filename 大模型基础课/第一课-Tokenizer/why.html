为什么需要分词？

一句话：神经网络只会做数学，不认识文字。Tokenizer 是把「人类语言」翻译成「模型能吃的数字序列」的第一道、也是唯一一道确定性工序。

① 模型眼里没有"字"，只有"向量"

大语言模型的内部全是矩阵乘法与浮点运算。它无法直接处理字符串 "你好"，只能处理数字。于是任何一段文本进入模型前，都要经过一条固定的流水线：

原始文本  →  切成 token  →  查词表得到整数 ID  →  查 embedding 表得到向量  →  进入 Transformer
"tokenizer"  →  ["token","izer"]  →  [3110, 7509]  →  [[0.02,-0.5,...],[...]]  →  ...

其中「切成 token」+「查词表得 ID」这两步合起来，就是 tokenizer（分词器）在做的事。它是纯粹的、可逆的、无参数（或极少参数）的映射，不参与梯度训练——但它决定了模型"看世界的最小单位"。

💡 token 是模型的"原子"
模型能表达的一切，都以 token 为最小单位。词表里没有的东西，模型只能用几个更小的 token 拼出来。所以分词方式直接影响：序列长度（=算力成本）、罕见词/多语言/代码的表达效率、甚至数学能力。

② 那么，最小单位该多大？这是全部问题的核心

把文本切成"离散单元"，粒度可粗可细，构成一条光谱。粒度的选择是一场三方权衡：

粒度词表大小序列长度未登录词(OOV)语义
词级 word极大（数十万+）短严重强
字符级 char极小（几十~几千）很长无弱
词片级 subword ⭐适中（3万~20万）适中几乎为零较强
字节级 byte极小(256)+合并可控彻底为零较强

三个互相拉扯的目标：

  • 词表要小——词表就是模型输出层 softmax 的宽度，也是 embedding 矩阵的行数。词表越大，参数越多、训练越慢、罕见 token 越难学好。
  • 序列要短——Transformer 自注意力是 O(n²)。同一句话切出的 token 越多，算力和显存开销越大、上下文越"不经用"。
  • 不能有未登录词——一旦遇到词表里没有的东西（新词、错字、别的语言、emoji），要能优雅降级，而不是吐一个 [UNK] 把信息丢掉。
🎯 subword / byte-level 为什么赢
词片级和字节级正好落在这条光谱的"甜点区"：词表适中、序列不长、几乎/彻底消灭 OOV。常用词整体成一个 token（高效），罕见词自动拆成更小的已知片段（不丢信息）。这就是今天几乎所有大模型都用 subword / byte-level 的根本原因——方法时间线里会把它们一个个讲透。

③ 一个直觉例子

同一句 "unhappiness"：

  • 词级：如果训练语料里没出现过这个词 → [UNK]，信息全丢。
  • 字符级：u n h a p p i n e s s → 11 个 token，序列很长，模型还得自己重新学"这些字母连起来啥意思"。
  • 词片级：un + happ + iness 或 un + happiness → 2~3 个 token，既短又保留了"un-"否定前缀这种可复用的语义积木。
