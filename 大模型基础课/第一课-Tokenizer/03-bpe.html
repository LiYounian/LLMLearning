BPE：字节对编码

Byte Pair Encoding 是今天绝大多数生成式大模型分词器的算法底座。核心朴素到一句话就能说清：反复把语料里出现最频繁的一对相邻符号，合并成一个新符号。

📜 出身
BPE 最早是 1994 年 Philip Gage 提出的一种数据压缩算法，跟 NLP 毫无关系。2016 年 Sennrich 等人把它"借"来处理机器翻译里的稀有词，从此开启了 subword 时代[2]。它的思想和压缩一脉相承：高频的组合值得用一个更短的符号来表示。

① 训练：怎么"学"出一套合并规则

给定语料，BPE 训练产出的是一份有序的合并规则表（merge list）。算法如下：

  1. 初始化：把每个词拆成单个字符序列，末尾加一个词尾标记（如 </w>，本页可视化里用 ◻ 表示）。此时词表 = 所有出现过的字符。
  2. 统计：数一遍语料里所有相邻符号对的出现频次。
  3. 合并：挑出频次最高的那一对，合并成一个新符号，加入词表，并把这条规则追加到 merge list。
  4. 重复 第 2–3 步，直到达到预设的词表大小（或没有值得合并的对为止）。
🔑 关键点：合并是"有序"的
merge list 是有先后顺序的。规则 e+s→es 必须先于 es+t→est。推理时也严格按这个顺序应用——这保证了训练和推理切法一致、结果确定。

③ 为什么这么做有效？

  • 高频词整体成 token：像 the、ing 这种高频组合会被反复合并，最终变成单个 token → 序列短、高效。
  • 低频词自动降级：罕见词没被合并到底，就留在较小的片段状态 → 不丢信息，也不炸词表。
  • 确定性 & 可逆：同样的 merge list，任何文本切法唯一；把 token 拼回去就能无损还原原文。
  • 数据驱动：切分粒度不是人拍脑袋定的，而是从语料统计里自然涌现的——语料里常见什么，什么就成为一个 token。

④ 伪代码

# 训练
vocab = 所有字符
merges = []
while len(vocab) < 目标词表大小:
    pairs = 统计语料中所有相邻符号对的频次
    best  = argmax(pairs)           # 最高频的一对
    if pairs[best] < 2: break
    合并语料中所有 best 出现处
    vocab.add(best[0] + best[1])
    merges.append(best)             # 记录规则（有序！）

# 推理（切分新词）
def encode(word):
    seq = list(word) + ["</w>"]
    for (a, b) in merges:           # 严格按训练顺序
        seq = 把 seq 中相邻的 (a,b) 都替换成 a+b
    return seq
