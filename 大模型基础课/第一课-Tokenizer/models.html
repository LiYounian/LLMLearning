模型 × 方法：谁用了什么分词器

直接回答那个最常见的问题：GPT、Qwen、DeepSeek 今天基本都是同一套范式——字节级 BPE（byte-level BPE）。差异主要在词表大小、正则预切分规则、和工程细节。也有例外（早期 LLaMA、Gemma 走 SentencePiece）。

每个方法点进去看详解；这里快速看它"花落谁家"：

✅ 一句话结论
生成式大模型的分词器已经高度收敛到 字节级 BPE 这一条路线（GPT-2 开的头）。区别只在"词表多大、预切分怎么切"。想亲眼看差距，去 切词对比页。

③ 逐家要点

GPT（OpenAI）：一路 tiktoken，全程字节级

  • GPT-2/3：r50k_base，5 万词表，不拆数字。
  • GPT-3.5/4：cl100k_base，约 10 万，数字按 1~3 位分组（\p{N}{1,3}）。
  • GPT-4o / o 系列：o200k_base，约 20 万，多语言尤其 CJK 压缩优化。

Qwen（阿里）：官方明说"在字节上跑 BPE、用 tiktoken"

三个易混数字：151,643（BPE token 数）/ ~151,665（加特殊 token）/ 151,936（embedding 行数，为对齐硬件 padding）。中文压缩到约 1 token/1.5–1.8 字。

DeepSeek：V2 词表 10 万、V3 12.8 万

V3 预切分把"标点+换行合并成一个 token"以提升多语言压缩，会带来 token 边界偏置，训练时随机拆开一定比例缓解。

LLaMA：一次典型的"路线迁移"

LLaMA 1/2 = SentencePiece-BPE（3.2 万、数字逐位拆、byte-fallback）；LLaMA 3 = tiktoken 风格字节级 BPE（12.8 万）。"SentencePiece 32K → tiktoken 128K"正是行业往"更大、字节级"收敛的缩影。

⚠️ Kimi 的诚实标注
Kimi K2（开源）用字节级 BPE，词表约 16 万，与主流一致。但 k1 / k1.5 是闭源 API 模型，Moonshot 未公开分词器细节和词表——只能推断沿用字节级 BPE，不能给准数字。

④ 一个大趋势：词表越做越大

词表规模代表模型
~50kGPT-2 / GPT-3
~100kGPT-3.5 / GPT-4 (cl100k)
~128kLLaMA 3 / DeepSeek-V3
~152kQwen
~160kKimi K2
~200kGPT-4o
~256kGemma

为什么变大：压缩率更好（更少 token → 省 O(n²) 算力、上下文更经用、API 更便宜），多语言/CJK/代码受益最大。为什么不无限大：embedding/输出层参数线性膨胀、稀有 token 训练不足（glitch token）、收益递减。当前主流落在 128k–256k。详见 tiktoken 大词表页 与 前沿页。
