2021–2025 · 研究前沿

前沿：大模型正在"抛弃分词器"吗？

分词器被越来越多研究者称为"大模型流水线里最后一个 hack"——一个独立、不可微、单独统计训练的预处理阶段，硬焊在一个本该端到端学习的模型前面。这一节讲清它的病根、正在替代它的技术，以及 2026 年的真实现状。

代表工作： ByT5 · CANINE MegaByte · BLT MambaByte · H-Net T-FREE · SuperBPE

① 病根：为什么说分词器是"最后一个 hack"

Karpathy 那句广为流传的话点破了要害：相当一部分大模型的"抽风"，是分词器的错，不是模型的错[1]。具体症状：

  • 数字与算术：BPE 对数字的合并前后不一致——677 可能是 1 个 token，678 却是 2 个。模型看不到数字干净的位值分解，算术脆弱的一大嫌疑源头。对策：强制单个数字成 token（LLaMA、PaLM）或按位分组。
  • Glitch token（幽灵 token）：像 SolidGoldMagikarp 这种词，在分词器训练语料里高频（Reddit 用户名），却几乎没出现在模型训练语料里，导致它的 embedding 停留在随机初始化附近，一喂就让模型胡言乱语。"Fishing for Magikarp"[2] 证明这类欠训练 token 在各大生产模型里普遍存在。病根就是分词器训练与模型训练两套语料、两个目标，彼此脱节。
  • 非英语被"征税"：词表以英语/拉丁字母为主，同样的意思在中文/泰文/缅甸文里被切成 2–5 倍的 token → ① API 更贵 ② 上下文窗口实际更短 ③ 质量更差。这是 tokenizer-free 路线的核心动机之一。
  • 空格 / 代码 / 缩进：前导空格算进 token（" the"≠"the"），连续空格/制表符切法混乱，坑 Python 缩进。GPT-4 专门硬编码了多空格 token 来打补丁——反证问题真实存在。
  • 提示边界的玄学：prompt 结尾停在一个"自然 token"中间，会把模型推离训练分布（著名的"结尾空格问题"）。
🧬 一元论
所有这些症状都是同一个病：一张手工设计、冻结、不参与梯度的词表，坐在梯度通路之外。前沿议程就三个字——缩小它、学习它、或干掉它。

② 第一波尝试（2021）：直接吃字节/字符

ByT5

直接吃 UTF-8 字节

词表就 256+特殊符，无分词器。重编码器/轻解码器抵消长度。对噪声/错字/大小写明显更鲁棒，拼写类任务更强。[3]

2021鲁棒性
CANINE

字符级编码器

直接吃 Unicode 码点、无词表。用下采样（局部注意力→步长卷积→深层 Transformer→上采样）控长度。多语言 QA 超过 mBERT。[4]

2021下采样
Charformer

可微分子词(GBST)

让"如何把字符池化成子词"变成模型里可梯度训练的一部分。"学出来的切分"这一思想的种子。[5]

2021可学习切分

③ 关键突破：动态字节分块，绕开 O(n²) 长度税

字节序列比 token 长约 4 倍，注意力 O(n²) 直接劝退。统一思路：别让大 Transformer 逐字节跑，先把字节打包成"块(patch)"，大部分算力花在块级别。

MegaByte（2023, Meta）

把字节切成固定大小的块（4–8 字节），大的"全局"模型跑短的块序列，小的"局部"模型预测块内字节。能到百万字节级序列，困惑度可与子词 Transformer 抗衡。[6] 遗留问题：块是定长的，不管内容好不好预测都花一样的算力——这正是 BLT 要修的。

⭐ BLT · Byte Latent Transformer（2024, Meta）—— 本节的重头戏
第一个在规模上追平"带分词器"大模型（8B 参数、4T 训练字节、FLOP 对齐的严格对比）、同时完全没有固定词表的字节级架构。[7]

核心创新——基于熵的动态分块：块的边界由"下一个字节有多难预测"动态决定：

  1. 一个小的字节级"熵模型"（迷你自回归字节 LM）估计下一个字节分布的熵——即有多"意外"。
  2. 高熵（难预测、像新词开头/罕见串）→ 开一个新块；低熵（可预测、常见词中段/套话）→ 延长当前块。
  3. 结果：可预测的文本用长块，难啃的文本用短块——算力被分配到数据复杂的地方。块长变成内容自适应的。

结论：① 首个把字节模型做 FLOP 对齐扩到 8B/4T 的研究，追平 Llama-3 级模型；② 固定推理成本下扩展性更好；③ 字符操作、加噪、长尾、低资源上更鲁棒；④ 没有词表 → 天然没有 glitch token、没有非英语税、没有数字病。第①节那些病，从根上治好了。

亲手体验熵动态分块（可交互）：拖动阈值滑块，看字节序列如何按"下一字节有多难预测"被切成变长的块——可预测处并成长块、难啃处切成短块。

MambaByte（2024）

换个思路：把 O(n²) 的 Transformer 换成 Mamba 状态空间模型，靠定长循环状态让长字节序列变便宜（线性时间）。直接吃原始字节，LM 能力可与子词 Transformer 抗衡，解码提速约 2.6×。[8]

④ 另一支：不动序列长度，改削词表参数

  • T-FREE（2024）：保留"词"为单位，但扔掉学出来的词表——把每个词编码成字符三元组的稀疏哈希激活。无词表 → 无 glitch、无 OOV；embedding/输出层参数减少 >85%，跨语言迁移更好。[9]
  • 多 token 预测（2024）：不是分词方案，但同源——每步用多个头并行预测后 n 个 token，训练无额外开销、自投机解码提速约 3×，已在 DeepSeek-V3 等生产模型出现。[10]
  • 词表的 Scaling Law（2024）：证明词表也是个可扩展变量，计算最优的词表大小随模型增大而增大——大多数大模型其实"词表不够大"（70B 级最优约 20 万 vs 常用 3.2 万）。这为行业往 128k–256k 漂移提供了理论依据。[11]

⑤ 2025 最新：改良派 vs 革命派

  • SuperBPE（2025，改良派）：两阶段 BPE，先学子词、再放开空格边界学"超级词"（把多词短语当成一个 token）。20 万词表下 token 数最多减 33%，30 个任务平均 +4.0%（MMLU +8.2%）、推理算力少 27%——罕见的免费午餐。[12]
  • 分词器移植（2024–25）：不重训就换掉模型的分词器。ZeTT 用超网络把"任意分词器→embedding 矩阵"[13]；免训练 OMP 用锚点 token 的稀疏线性组合重建新 token[14]。分词器变成可热插拔组件。
  • H-Net（2025，革命派）：最激进——在模型内部端到端学出字节分块，靠可微的"动态分块"，不要熵模型、不要启发式、不要外部分词器。算力/数据对齐下，单层 H-Net 超过强 BPE Transformer，字符鲁棒性大涨；是 MambaByte/BLT 的自然接班人。[15]

⑥ 总轨迹 & 2026 年真实现状

词级        （词表小，OOV 灾难）
  ↓
字符级      （无 OOV，但序列长、语义薄）
  ↓
子词 BPE/WordPiece/Unigram  （2016–2024 主力，甜点区）
  ↓
字节级 BPE  （GPT-2 起：无 OOV、Unicode 安全——但第①节的病全保留）
  ↓
前沿：动态字节分块(BLT) / 端到端学习分块(H-Net) / tokenizer-free(ByT5,T-FREE,MambaByte)
      + 改良支线：更大词表 / 超级词(Scaling-Laws-with-Vocab, SuperBPE)
🎯 一句话共识（2026）
分词器已不再被看作永久设施，而是"借来的时间上的遗留 hack"；但截至 2026 年它在生产中尚未被推翻。研究前沿明确朝"可学习、可微、内容自适应的分块"走（BLT、H-Net 都已越过"字节模型规模上打不过子词模型"这道十年门槛）；但所有在跑的旗舰大模型仍然用大词表(128k–256k)的字节级 BPE——快、便宜、经过实战、且整个服务栈(KV-cache、计费)都是按 token 建的。聪明钱押的是渐进迁移（动态字节分块/学习分块），而非一夜废除。
