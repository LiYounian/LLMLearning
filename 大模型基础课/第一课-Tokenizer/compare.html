目录 / 切词对比（真实数据）

同一句话，各家切成几个 token？

这一页的数字不是估的——是用真实分词器（GPT 系走 tiktoken，Qwen/DeepSeek/LLaMA/BERT/T5 走 HuggingFace）现跑出来的。同一段文本喂给 8 个分词器，看它切成多少 token、具体怎么切。生成脚本见 scripts/gen_token_compare.py。

🎯 一句话看点
token 数 = 你的 API 账单 + 占用的上下文长度。词表越大、越针对某语言优化，同样内容切出的 token 越少 → 越便宜、上下文越经用。下面选不同样本，尤其看中文和长数字两个样本的差距。

③ 从真实数据里读出的三件事

㈠ 中文被狠狠"征税"，但差距在飞快缩小

同一句中文，用真实分词器跑出来：

  • GPT-2（5万词表、英文导向）：54 个 token——几乎每个汉字被拆成 3 个字节碎片（看上面切分里满屏的红 ▪）。
  • GPT-4o(o200k)：20；Qwen2.5：17；DeepSeek-V3：15（最省，甚至把"深度学习"整体压成 1 个 token）。

从 54 → 15，同样一句中文，token 数差 3.6 倍。这就是 大词表 + 针对中文优化合并的真金白银收益：更便宜、上下文更经用。

㈡ 数字：Qwen 故意"逐位拆"，所以数字样本反而最长

"长数字"那一行，Qwen2.5 = 33 个 token，明显高于其它家的 ~21。不是 Qwen 差，而是它刻意把每个数字拆成单独 token（LLaMA、PaLM 也这么干）——为的是让模型看到干净的位值分解，提升算术能力。这正是 前沿页 讲的"数字/算术"问题的一种对策，在数据里看得清清楚楚。

㈢ 英文基本打平

纯英文句子，几乎所有分词器都切成 10 个 token（T5 = 12）。因为它们的合并规则都在英文语料上训练得很充分，常用英文词早就整体成 token 了。差距只在非英语和特殊内容上才拉开——这也是为什么"词表变大"主要利好中文/多语言/代码。
