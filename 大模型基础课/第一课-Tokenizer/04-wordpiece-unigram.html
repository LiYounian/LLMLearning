WordPiece 与 Unigram

BPE 用频次决定合并谁。但"最高频"真的等于"最该合并"吗？这一节看另外两条路线：WordPiece 改用似然来合并（BERT 用它），Unigram 干脆反着来——从大词表往下剪枝（T5、多语言模型用它）。

① WordPiece：按"似然增益"合并（自底向上）

出身：Schuster & Nakajima 2012 为日韩语音搜索提出[3]，2019 年被 BERT 发扬光大[4]。方向和 BPE 一样是自底向上合并，唯一的区别在选谁来合并：

🔑 与 BPE 的唯一差别（一行讲清）
BPE 按 freq(ab) 排序（原始频次）；
WordPiece 按 freq(ab) / (freq(a)·freq(b)) 排序（似然增益比）。

为什么是这个比值？在一个 unigram 语言模型 p(t)=freq(t)/总数 下，把 a,b 合成 ab 带来的对数似然变化正比于 log[ freq(ab) / (freq(a)·freq(b)) ]。所以最大化这个比值 = 最大化训练语料的似然。

它的效果：这个比值会惩罚"本身就很常见"的片段。比如 the 到处都是，光看频次它跟谁组合频次都高；但除以各自频次后，只有那些"合起来出现的概率远高于各自独立出现"的组合才会胜出——也就是真正像"词"的组合。

训练与推理

  • 训练：初始化词表 = 所有字符的两种形态（词首形态、词内 ## 形态）。反复挑freq(ab)/(freq(a)·freq(b))最高的对合并，直到词表达标。
  • 推理：贪心最长匹配——从词首找词表里最长的前缀切下来，往后重复。unaffable → un ##aff ##able。如果剩余部分怎么都匹配不到词表 → 整个词变 [UNK]。
📌 ## 是什么
词内（非开头）的片段带 ## 前缀：playing → play + ##ing。不带 ## 的片段可以做词首；带 ## 的必须接在前面。这跟 SentencePiece 的 ▁ 恰好相反——## 标记"前面没有空格"，▁ 标记"前面有空格"。

相对 BPE 的权衡：似然准则给出更"信息量大"的片段（不会因为频次高就乱合并）。缺点：贪心最长匹配可能局部次优；解不出来的词直接整词 [UNK]——所以在"零 OOV"这点上不如字节级 BPE 硬。

② Unigram：从大词表往下剪枝（自顶向下）

出身：Taku Kudo 2018[6]。它和 BPE/WordPiece 的方向完全相反：不是从字符往上拼，而是先搞一个很大的候选词表，再迭代剪掉"删了最不心疼"的 token，直到缩到目标大小。

核心模型

每个 token 都带一个概率 p(x)，一段文本的一种切分 x=(x₁…x_M) 的概率 = ∏ p(xᵢ)。同一个词因此有很多种可能切分，各有概率。

训练（种子词表 → EM 剪枝）：

  1. 构造一个大种子词表（所有字符 + 高频子串）。字符必须全留，保证覆盖。
  2. 用 EM 算法重估每个 token 的概率 p(x)（在所有可能切分的格上做前向-后向）。
  3. 对每个 token 算"删掉它，语料总似然会掉多少"（= loss）。
  4. 保留所有单字符，剪掉 loss 最小的一批（如底部 10–20%）。回到第 2 步，直到词表缩到目标。

推理：默认用 Viterbi 找概率最大的那一种切分；训练时也可以按概率采样不同切分——这就是 Kudo 提出的 subword regularization（子词正则），相当于数据增强，能提升鲁棒性（尤其低资源/跨域）。

③ SentencePiece：不是新算法，是"框架"

常有人把 SentencePiece 当成一种分词算法，其实它是个库/框架（Kudo & Richardson 2018[7]），里面同时实现了 BPE 和 Unigram。它真正的贡献是一个工程改造：

🔑 ▁ 的妙处：把空格当普通字符
SentencePiece 把输入当成原始 Unicode 流，不做任何语言相关的预分词，而是把每个空格替换成元字符 ▁(U+2581)。"Hello world" → ▁Hello▁world。于是：
① 无损可逆：text == decode(encode(text))，把 token 拼回、▁换回空格就还原了；
② 语言无关：中文/日文/泰文这种没空格的语言不再需要 jieba/MeCab 之类的预处理器。

这就是为什么它成了多语言模型（mBART、T5、XLM-R）和 LLaMA 1/2 的标配。算法还是 BPE/Unigram，贡献是让整条分词管线端到端、可逆、语言无关。
