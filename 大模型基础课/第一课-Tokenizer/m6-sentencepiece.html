SentencePiece：让分词语言无关、可逆

它不是一种新算法，而是一个库 / 框架，内含 BPE 和 Unigram 两种模式；真正的贡献是把输入当作原始 Unicode 流、用 ▁ 表示空格，从而做到语言无关 + 无损可逆。

被这些模型使用：LLaMA 1/2T5GemmaXLM-RmBART

① 出身：一篇 EMNLP 系统演示论文

SentencePiece 由 Google 的 Taku Kudo 与 John Richardson 在 2018 年提出，发表于 EMNLP 2018 系统演示（System Demonstrations），论文题为 SentencePiece: A Simple and Language Independent Subword Tokenizer and Detokenizer for Neural Text Processing[6]。注意作者 Taku Kudo 也正是前一节 Unigram 算法（2018 ACL）的作者——SentencePiece 可以看成他把 Unigram / BPE「产品化」的工程成果，代码开源在 github.com/google/sentencepiece。

⚠️ 先破除一个常见误解：SentencePiece 不是「一种分词算法」
很多人把 SentencePiece 和 BPE、WordPiece、Unigram 并列，当成「第四种算法」——这是错的。SentencePiece 是一个框架 / 实现库，它内部既能跑 BPE、也能跑 Unigram（还支持 char / word 模式）。它本身没有发明新的「怎么学词表」的算法；学词表这一步完全复用 BPE（前面第 3 节）或 Unigram（第 5 节）。它的真正贡献在预处理与工程封装：把整条流水线做成语言无关、无损可逆的。所以正确的说法是「SentencePiece-BPE 模式」「SentencePiece-Unigram 模式」，而不是「SentencePiece 算法」。

② 核心机制：▁ 空格技巧 + 语言无关流水线

在 SentencePiece 之前，subword 分词有一个隐藏的脏活：预切分（pre-tokenization）。BPE / WordPiece 都假设文本已经先按空格和标点切成了「词」，再在词内部做子词合并。对英文，这一步靠 Moses、Penn Treebank 之类的规则切分器；但对中文、日文、泰文这些没有空格的语言（scriptio continua），你必须先上 jieba、MeCab 这类语言相关的分词器。这既脆弱又不可移植：换一种语言就要换一套预处理，而且分词器的切法和后续子词模型不一致，还原时也要靠一堆启发式规则拼回空格。

SentencePiece 的解法是把这一步整个删掉：直接把输入当作一串原始 Unicode 字符（空格也是普通字符之一），端到端处理。关键就在于怎么处理空格——它引入了一个元符号 ▁（U+2581，"下八分之一块" lower one-eighth block），专门用来编码空格。整条流水线是这样的：

  1. 归一化（normalize）：对原始文本做 Unicode 归一化，默认 NFKC。不需要任何分词器、Moses 或 jieba。
  2. 空格 → ▁：把每个空格替换成 ▁。习惯上还会在整段文本开头补一个 ▁，让第一个词和其他词受到一致对待。例："Hello world" → ▁Hello▁world。
  3. 在这个流上跑 BPE 或 Unigram：此时空格已经是普通字符，直接在这串符号上做子词合并 / 剪枝。学出来的 token 长这样：▁Hello、▁world、▁the、ing……一个 token 前面带 ▁ 就代表「它前面本来有个空格」。
  4. 拼回、▁ → 空格，即无损还原：解码时把所有 token 直接拼接，再把 ▁ 换回空格。没有任何启发式规则，天然精确 round-trip。
🔑 两个直接好处
  • 语言无关：不需要 jieba / MeCab 之类语言相关的预处理。对中日泰这种无空格语言尤其重要——它们分词后本来就没有空格，▁ 自然不会出现在词内部，流水线一视同仁。
  • 无损可逆：text == decode(encode(text)) 严格成立。因为空格被当成数据一起编码，还原时不靠猜。这对需要精确复现原文的场景（代码、格式敏感文本）是硬需求。

▁ 与 WordPiece 的 ## 正好相反

两者都在标记「词边界」，但标记的东西正相反，很容易记混：

标记含义出现位置例子
▁（SentencePiece）「我前面有一个空格」（词的开头）词首片段带 ▁▁Hello · ▁world
##（WordPiece）「我前面没有空格」（接在上一片段后）词内片段带 ##play · ##ing

换句话说：▁ 标「前面有空格」，## 标「前面没空格」——一个正向标词首，一个反向标词内。

③ 具体用法与例子

训练一份 SentencePiece 模型，核心就两个参数：用哪种算法、词表多大。

# 训练（伪命令行）
spm_train \
  --input=corpus.txt \
  --model_type=bpe|unigram \   # 选算法：BPE 或 Unigram（默认 unigram）
  --vocab_size=32000 \         # 目标词表大小
  --character_coverage=0.9995  # 多语言/CJK 常调这个

# 结果产物：tokenizer.model（词表 + 参数）

用 --model_type=bpe 就走第 3 节的 BPE 合并逻辑，用 --model_type=unigram（默认）就走第 5 节的 EM 剪枝 + Viterbi 逻辑；--vocab_size 控制最终词表大小。学词表这一步和前面两节讲的完全一样，唯一区别是它跑在 ▁ 编码后的原始流上、并套了自己的归一化。

一个具体的编码 / 解码往返：

encode("Hello world")
  → 归一化 + 空格转 ▁ :  "▁Hello▁world"
  → 子词切分（BPE/Unigram）:  ["▁Hello", "▁world"]

decode(["▁Hello", "▁world"])
  → 拼接:  "▁Hello▁world"
  → ▁ 换回空格:  "Hello world"   ✅ 与原文逐字节一致

对中文这种无空格文本，例如 "今天天气"，归一化后不会插入 ▁（词内没有空格），子词模型直接在汉字流上切，还原时也不会凭空多出空格——这正是语言无关设计省下的麻烦。

④ 优缺点与影响

  • 优点：真正端到端、可逆、语言无关。去掉了脆弱的、语言相关的预切分步骤，把空格当数据处理，使得同一套流水线可以直接用于任意语言，且严格无损还原。这是它成为多语言 / 开源模型事实标准的根本原因。
  • 优点：算法可插拔。BPE 要确定性、Unigram 要概率化 + 子词正则（subword regularization），换个参数即可，不用换库。
  • 代价：全流水线要统一约定。你必须在整个训练 + 推理链路上锁定它的归一化方式（NFKC 等）和 ▁ 约定，一旦某一端不一致就会 token 错位。
  • 注意：算法层的取舍仍继承自内核。选 BPE 就继承 BPE 的贪心 + 确定性缺点，选 Unigram 就继承 Unigram 的训练更重但更稳健——SentencePiece 本身不改变这些。

⑤ 被哪些模型使用

SentencePiece 是多语言 / 开源模型早期的事实标准，尤其在「tiktoken 大词表时代」到来之前。具体点名：

模型SentencePiece 模式词表大小特殊处理
LLaMA 1 / 2BPE 模式32,000数字逐位拆分（每个数字单独成 token，利于算术泛化）；byte-fallback 兜底词表外字符（回退成 UTF-8 字节 token，因此也不会真吐 unk）[9]
T5Unigram 模式~32kGoogle 的多语言文本到文本模型，Unigram 是 SentencePiece 的默认算法
GemmaSentencePiece256,000（超大词表）含 split-digits + 字节级编码兜底，对多语言极友好；Gemma 3 与 Gemini 2.0 共用同一 SentencePiece[13]
XLM-RSentencePiece多语言大词表跨语言表示学习的代表作，靠 SentencePiece 的语言无关性覆盖上百种语言
mBARTSentencePiece多语言多语言去噪自编码翻译模型，同样依赖语言无关流水线

补充一个关键叙事：LLaMA 系列后来「叛变」了。LLaMA 1 / 2 用的是 SentencePiece-BPE（32k 词表），但到了 LLaMA 3 就转向了 tiktoken 风格的字节级 BPE，词表也从 32k 一举放大到 128,256。这次迁移是「SentencePiece → tiktoken」路线切换的典型案例，也标志着大词表时代的到来——正是下一页的主题。

📎 小结 & 承上启下
SentencePiece 的价值不在「发明算法」，而在「把 subword 分词做成语言无关、可逆、端到端」。它内含 BPE / Unigram 两个内核，用 ▁ 把空格当数据，删掉了脆弱的语言相关预切分，因此成了多语言与开源模型（LLaMA 1/2、T5、Gemma、XLM-R、mBART）早期的默认选择。
但故事在 2019 年 GPT-2 之后开始分岔：另一条路线不做 Unicode 字符、也不依赖 SentencePiece 的归一化，而是直接在 256 个字节上跑 BPE。下一节先看这条字节级 BPE路线的机制，再进入它催生的「大词表时代」——连 LLaMA 3 都最终投奔了过去。
