主流大模型到底用什么分词器？

直接回答你的问题：是的，GPT、Qwen、DeepSeek 今天基本都是同一套范式——字节级 BPE（byte-level BPE）。差异主要在词表大小、正则预切分规则、和一些工程细节上。也有例外（早期 LLaMA、Gemma 走 SentencePiece），下面逐个拆。

✅ 一句话结论
生成式大模型的分词器已经高度收敛到 byte-level BPE 这一条路线（GPT-2 开的头）。你说的"把字符转成编码再按组合统计"——完全正确，只不过用的编码是 UTF-8 字节，统计合并发生在字节流上。区别只在"词表多大、预切分怎么切"。

② 逐家拆解

GPT 家族（OpenAI）：一路 tiktoken，全程字节级

从 GPT-2 起就是 byte-level BPE，实现库是 OpenAI 自家的 tiktoken。演化主要体现在词表变大 + 正则预切分升级：

  • GPT-2/3：r50k_base，5 万词表，不拆数字。
  • GPT-3.5/4：cl100k_base，约 10 万词表，正则改成数字按 1~3 位分组（\p{N}{1,3}）——这对算术能力有帮助。
  • GPT-4o / o 系列：o200k_base，约 20 万词表，对多语言尤其 CJK 的压缩进一步优化。
📌 精确词表数字的坑
cl100k_base、o200k_base 的"精确"大小取决于是否把特殊 token 计入，所以课件写"约 10 万 / 约 20 万"最稳妥。可用 tiktoken 源码 openai_public.py 核对。

Qwen（阿里）：官方明说"在字节上跑 BPE、用 tiktoken"

Qwen 全系 byte-level BPE，tiktoken 风格。这里有个三数字易混陷阱，务必分清：

  • 151,643 = BPE 常规 token 数；
  • 加上特殊 token 后约 151,665；
  • embedding 矩阵行数补齐到 151,936 / 152,064（config 里 vocab_size 常见 151,936）——为了对齐硬件/并行做的 padding。

中文压缩到约 1 token / 1.5–1.8 字，比早期 5 万词表的英文导向模型友好得多。

DeepSeek：字节级 BPE，V3 加了标点/换行合并优化

  • V2：词表 100,000（config 102,400）。
  • V3：词表 128,000（config 129,280）。预切分引入"标点+换行合并成一个 token"来提升多语言压缩率，但这会带来 token 边界偏置，训练时会随机拆开一定比例来缓解。

LLaMA：一次典型的"路线迁移"

LLaMA 是很好的对照案例，因为它换过路线：

  • LLaMA 1/2：SentencePiece-BPE，词表仅 32,000，数字逐位拆分，▁ 表空格，byte-fallback 兜底。
  • LLaMA 3/3.1：改用 tiktoken 风格 byte-level BPE，词表跳到 128,256（10 万基础 + 约 2.87 万多语言/代码 token）。

"SentencePiece 32K → tiktoken 128K"这一跳，正是整个行业往"更大、字节级"收敛的缩影。

Kimi / Moonshot：K2 走字节级 BPE，早期闭源型号未公开

⚠️ 诚实标注信息边界
Kimi K2（开源）用 byte-level BPE（regex + BPE 流水线），词表约 16 万，与主流一致。但 k1 / k1.5 是闭源 API 模型，Moonshot 没公开分词器细节和词表大小——k1.5 的技术报告只讲强化学习与长思维链，没提 tokenizer。所以对 k1/k1.5 我们只能推断它沿用字节级 BPE，不能给准数字。这一点如实告诉你，避免编造。

③ 一个大趋势：词表越做越大

近 5 年主流词表放大了 4–5 倍：

词表规模代表模型
~50kGPT-2 / GPT-3
~100kGPT-3.5 / GPT-4 (cl100k)
~128kLLaMA 3 / DeepSeek-V3
~152kQwen
~160kKimi K2
~200kGPT-4o
~256kGemma

为什么变大：

  • 压缩率更好：同样文本切出更少 token → 省算力（注意力 O(n²)）、有效上下文更长、API 更便宜。
  • 多语言 / CJK / 代码受益最大：早期 5 万词表英文导向，一个汉字被拆成 2–3 个字节 token；扩表并为中文学专门的合并后，中文效率大幅提升。

为什么不无限大：

  • Embedding / 输出层参数线性膨胀：参数量 = 词表 × 隐藏维度，中小模型里 embedding 占比会高得离谱。
  • 稀有 token 训练不足：极少出现的 token 学不好，产生 glitch token（著名的 SolidGoldMagikarp）——详见前沿页。
  • 收益递减：32k→128k 收益明显，再往上边际收益变小而成本持续涨。

所以当前主流落在 128k–256k 这个折中区间。
