技术点深挖：三个关键机制的原理

从技术脉络里挑出三个"读懂了就抓住主线"的机制，讲清它解决什么问题、公式长什么样、和前代怎么取舍。面向已知道 Transformer/注意力基础的读者。

① MLA 多头潜在注意力 ② GRPO 组相对策略优化 ③ thinking-budget / 测试期算力 ④ MoE 负载均衡（延伸）

公式为便于阅读的线性写法（非严格 LaTeX 排版）；结构图为示意，非等比。一手来源见文末与来源页。

① MLA · 多头潜在注意力（DeepSeek V2 首创）

要解决的问题：自回归生成时，每生成一个 token 都要把历史所有 token 的 Key/Value 存进 KV cache。标准多头注意力（MHA）的 KV cache 大小 ∝ 头数×头维×层数×序列长——长上下文时显存被它吃满，成为推理成本与吞吐的头号瓶颈。GQA/MQA 通过"多个查询头共享一组 KV"来压缩，但要牺牲一点质量。

MLA 的思路：不直接缓存 K、V，而是把它们联合压缩成一个低维「潜在向量」 cKV（维度 dc ≪ 头数×头维），推理时只缓存这个潜在向量，用时再上投影还原出各头的 K、V。位置信息用一路解耦 RoPE 键单独携带。

# 下投影：把隐藏态压成低维潜在向量（这就是要缓存的东西） cKVt = WDKV · ht // dim d_c，远小于 n_h·d_h # 用时上投影，还原每个头的 Key / Value（W 可在推理时吸收进别的矩阵，不必真存） kCt = WUK · cKVt vCt = WUV · cKVt # 解耦 RoPE：另开一路小维度键携带位置，所有头共享 kRt = RoPE( WKR · ht ) // dim d_h^R # 最终每个头的键 = [还原键 ; 共享位置键] kt,i = [ kCt,i ; kRt ] ════ 推理时每 token 只缓存： c^KV_t (d_c) + k^R_t (d_h^R) ════
方案每 token KV cache（元素数）代价 / 特点
MHA2 · n_h · d_h质量最好，显存最贵
MQA2 · d_h最省，质量掉得多
GQA2 · n_g · d_h折中（Llama 2/Qwen2 采用）
MLAd_c + d_hR　(V2: 512+64=576)省得多且质量不降，长文本关键

一句话取舍：GQA 是"减少 KV 的份数"，MLA 是"把 KV 压成低维再存、用时还原"——同样的显存预算下 MLA 拿到更好的质量，代价是多了投影矩阵的计算（可在推理时被吸收）。后续 DeepSeek 又在 MLA 上叠稀疏注意力 DSA（V3.2）把复杂度从 O(L²) 降到 O(L·k)。

② GRPO · 组相对策略优化（DeepSeek 首创）

推理/数学任务奖励可用规则判定（答案对不对、格式合不合规），组内比较天然给出稳定基线，不必学 critic。

③ thinking-budget / 测试期算力（test-time compute）

核心范式转变：2024 年 o1 起，提升智能的杠杆从"训练期堆参数/数据"多了一条"推理期让模型多想一会儿"。模型在给出答案前先生成一段（通常隐藏的）思维链 CoT，思考的 token 越多、准确率越高——这就是测试期算力缩放（test-time scaling）。

为什么要"预算/档位"：既然多想=多花钱且收益递减，就得把"想多深"变成一个可调旋钮，让简单问题少想、难题多想。各家给了不同形态：

extended thinking（Claude）
显式可开关的思考模式，用 budget_tokens 直接给思考 token 上限；后续加 effort 档位。
Deep Think（Gemini）
并行思考——同时展开多条推理路径再聚合，换取更难题目的正确率（IMO 金牌级）。
thinking budget（Qwen3）
thinking / 非-thinking 统一在一个模型里，用显式 token 预算控制思考长度。
reasoning_effort（OpenAI/通用）
low / medium / high / xhigh 档位，本质是把思考 token 预算离散成几挡。
# 两条常见的测试期缩放路径 ① 单条更长： 让 CoT 更长 → 准确率随思考 token 近似 对数上升后饱和 ② 多条聚合： 采样 k 条独立解 → 多数投票 / 自洽（self-consistency） acc(k) 随 k 提升，Deep Think 属此类（并行思考） # 成本 ≈ 思考 token 数 × 单价，所以"档位"= 在准确率↔成本曲线上选工作点

和指标脉络的呼应：正是测试期算力把 AIME、GPQA、SWE-bench 等硬基准从"做不动"推到 90%+（见指标脉络）——但代价是单次调用成本与延迟大涨，于是 2026 又转向"token 效率"（用更少思考达到同等智能）。

④ MoE 负载均衡：辅助损失 vs 无辅助损失（延伸）

问题：MoE 每个 token 只激活少数专家（如 671B 里只用 37B）。但路由容易"旱涝不均"——热门专家被挤爆、冷门专家学不到东西，既浪费容量又拖慢训练。

辅助损失法（传统）
在主损失外加一个负载均衡辅助损失惩罚不均。副作用：这个额外目标会和语言建模目标"打架"，略伤性能。
无辅助损失（DeepSeek V3）
给每个专家一个可学习偏置，只用它调整路由选择、不进梯度：过载就调低、闲置就调高。均衡不靠伤害主损失来实现。
upcycling（Qwen 等）
不从零训 MoE，而是把训好的 dense 模型"回收"复制成多专家再继续训，省算力。
