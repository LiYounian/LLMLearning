## 2026-08-21 · 部署套件（阿里云静态站 · 推送即上线）

**做了什么**
- 新增门户 `index.html`：`:9501/` 落地页，卡片链到三条学习线（第一课/第二课/演进路线）。
- 新增 `deploy/` 部署套件：
  - `update.sh`：展示端自动更新（自定位仓库→`git fetch`→有新提交才 `reset --hard origin/main` + `clean -fd`；静态站无需重启；幂等、带日志）。
  - `llmlearning-update.service` + `.timer`：systemd 每 2 分钟轮询触发；`OnBootSec=1min`、`Persistent=true`。
  - `nginx-llmlearning.conf`：nginx 监听 9501、root=仓库、`charset utf-8`（中文目录名）、HTML 不缓存/资源短缓存。
  - `README.md`：一次性部署手册（安全组放行 9501 + deploy 用户 + 只读 deploy key + clone + nginx + 定时器 + 运维/排错）。
- `.gitignore` 加 `deploy/logs/`（避免 `git clean` 误删自身更新日志）。

**关键决策 / 教训**
- 方案对参考手册大幅精简：本项目纯静态、无后端/DB/采集/LLM，故**去掉健康检查/回滚/自愈那一整套**——静态文件 nginx 直接读、拉取即生效，没有"服务起不起来"的问题。托管选 nginx、更新选 systemd 定时轮询（用户拍板）。
- 展示端只读跟随远端：`reset --hard` + `clean -fd`，绝不本地改；`clean` 靠 `.gitignore` 保住 `deploy/logs/`。
- 分工现实：安全组（阿里云控制台）、`sudo`/systemd/nginx 均需 root，统筹窗口无服务器 SSH——故交付"套件 + 可照抄手册"，服务器侧一次性步骤由用户执行。systemd unit/nginx conf 真实文件放 `/etc`、不入库，手册即真源。

**验证**
- 本地 worktree 内文件语法自查；部署套件为服务器侧执行，真机验证待用户按手册跑一次（`curl 127.0.0.1:9501/` 得 200、`update.sh` 手动跑一轮）。

**分支 / PR**
- 分支 `feat/deploy`（基于 origin/main 73ac08e）；集成后本条即真源，服务器按 `deploy/README.md` 上线。
