## 2026-08-20 · 集成演进路线 v1 + 两线迁入独立分支/worktree

**做了什么**
- 集成「大模型演进路线」v1：合并 `feat/roadmap-8companies`（3 commit、17 文件、14 页）进 main——8 家详情页（GPT/Claude/Gemini/Llama/Qwen/DeepSeek/Kimi/豆包）+ 索引 + 跨家族交互时间线 + 技术/指标/数据/来源专题页 + assets。
- 更新根 README：演进路线状态「建设中」→「v1 完成（14 页）」。
- 两条线各自迁入独立分支/worktree（各自掌管工作区）：演进路线用 `feat/roadmap-8companies`（已 push origin）；基础课用 `feat/tokenizer`（本地，内容 == main 暂无可合，有新提交再 push）。

**关键决策 / 教训**
- **根 README 由统筹集中维护**：本轮实际发生过一次撞车——演进路线窗口在共享主仓树里手改了根 README 加自己索引行，与统筹已推到 main 的新 README 冲突。处理：让该窗口 `git restore README.md` 丢弃冗余改动，索引统一由统筹更新。规矩里"内容窗口不改根 README、状态变更报统筹"由此坐实。
- **跨会话可见性受限、且非全连通**：两个内容窗口互相看不见，且基础课窗口发不进统筹会话，只能经演进路线窗口中转回执。协调靠精确 session_id 投递 + 暗号 LLMCO-2026 识别。
- **合并全程用独立临时 worktree**，不碰共享主仓工作树（内含内容窗口 WIP），符合"main 只集成、别碰别人 WIP"。

**验证**
- `git diff --name-only origin/main origin/feat/roadmap-8companies`：17 文件全在 `大模型演进路线/`、不碰 README → 干净 `--no-ff` 合并、无冲突。
- 核验 `feat/tokenizer` 在 origin 不存在、无独有提交，确认基础课线本次无可合。

**遗留 / 下一步**
- 基础课线后续（收尾第一课 / 第二课）在 `feat/tokenizer` 上做，有产出再 push + 回执，由统筹集成。
- 各内容窗口若把 cwd 从共享主仓树迁到各自 worktree，主仓树即可退化为统筹专用集成树，彻底消除共享树互踩风险。

**分支 / PR**
- 合并 `feat/roadmap-8companies`（基于 a847a1b）进 main，独立临时 worktree `--no-ff`；同一集成里更新 README 状态 + 本条日志。

**做了什么**
- 新开"统筹窗口"（会话标题 `llm-coordinator-inbox`），承接 LLMLearning 全项目的任务派发、目录/文档规范、`main` 集成、跨窗口协调。

- 学习并对齐本机通用规范（`projects/内部沟通/`：Git 规范 / worktree 模式 / 文档维护）。
- 与两个内容窗口建立联系（跨会话消息 + 暗号 LLMCO-2026），对齐"暂停各自 git 操作、等统一 worktree 方案"。

**关键决策 / 教训**
- **顶层目录保持平级两目录**（`大模型基础课/` + `大模型演进路线/`），不做统一父目录归拢——两条线目录不重叠即天然解耦，改动最小、并行最安全（用户拍板）。
- **统筹 ≠ 指挥**：内容窗口按权限边界只对接各自用户，统筹窗口只"提议约定 + 集成 main"，采纳与否由各窗口用户点头。这是权限按会话隔离的正确姿态。
- **跨会话可见性受限、slug 名是观察者相对的**：两个内容窗口互相看不见，且看统筹窗口的名字各不相同（`llmlearning-2f` / `llmlearning-7b`）。协调靠精确 session_id 投递 + 暗号识别，不靠名字。
- 脚手架在独立 worktree/分支（`chore/project-scaffold`）里做、再集成 main，示范合规流程；`docs/` 与两条学习线目录不重叠，合并无冲突。
